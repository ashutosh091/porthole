A browser window in another country.

Porthole opens Chrome, Brave, Firefox or Safari through one of your servers or any WireGuard VPN location. Only that window travels. Your other apps, tabs and calls stay on your normal connection.

One window travels. Everything else stays home.

A system VPN moves your whole computer. Porthole gives each region its own local proxy port and points one browser instance at it. No routes, no network interfaces and no system VPN are touched.

01 · Add an exit

Your server or a VPN location

Point at any SSH server you can log into, or import a WireGuard .conf from your VPN provider’s manual setup page. Nothing to install on the server.

02 · Pick a browser

Chrome, Brave, Firefox or Safari

Each region gets its own browser profile, timezone and language, so it looks local. Several regions can be open side by side.

03 · Checked before it opens

No surprises, no leaks

Porthole confirms the exit country before the window opens. DNS and WebRTC go through the tunnel; if the tunnel drops, pages fail instead of using your real IP.

Safari, too

Safari can’t take a per-window proxy, so Porthole handles it differently on macOS:

  • Only a list of sites goes through the region: streaming services by default, or lists you define for travel, search, work or home. Everything else stays direct.
  • Your settings come back automatically when Safari quits, when you press Stop, or the next time Porthole starts after a crash.
  • Or route all of Safari when you really need to, with one click.
# profiles.toml
[pac_sets]
streaming = ["netflix.com", "nflxvideo.net",
             "primevideo.com", "tv.apple.com"]
travel    = ["skyscanner.net", "booking.com",
             "expedia.com", "airbnb.com"]
work      = ["grafana.example.com"]

# CLI
porthole launch uk -b safari
porthole launch us -b safari --sites travel

Menu bar app, or the command line

The desktop app lives in your menu bar or system tray: import a config, click a browser, done. The porthole CLI (macOS, Python 3.11+) does the same from a terminal and shares the same config file.

  • Shared or separate logins: one browser profile for every region, or separate ones per region or group.
  • Leak test in one click: IP, WebRTC and DNS checks through the profile.
  • Plain text config at ~/.config/porthole/profiles.toml.
# install with Homebrew
brew tap ashutosh091/tap && brew trust ashutosh091/tap
brew install ashutosh091/tap/porthole
brew install --cask ashutosh091/tap/porthole   # app

porthole list
porthole launch uk                 # Chrome via the UK
porthole launch us -b firefox
porthole status                    # exits and IPs
porthole down --all

Questions

Is Porthole a VPN?

No. It doesn’t provide servers and it doesn’t change your system network. It connects to exits you already have (your servers, or a VPN subscription’s WireGuard configs) and routes just one browser window through them.

Does it change my whole computer’s network?

For Chrome, Brave and Firefox, no: only the window Porthole opens uses the tunnel. Safari mode is the exception on macOS, because Safari only follows the system proxy; Porthole sets a proxy file that sends only the listed sites through the region and restores your settings when Safari quits.

Will my normal Chrome be affected?

No. Porthole starts a separate Chrome instance with its own data folder. Your everyday Chrome keeps its own profile and network.

Do I need admin rights or Docker?

The desktop app needs neither. The CLI uses Docker only for gluetun profiles. macOS may ask for your password when Safari mode changes the proxy setting.

Does it work with my VPN provider?

If your provider offers WireGuard configuration files (most do, under “manual setup”), yes. For OpenVPN-only providers, use the CLI with gluetun.

Why does a site still say I’m somewhere else?

Some VPN locations are virtual: the IP is registered in one country while the server sits in another, and geo-IP databases disagree. Porthole checks two databases and warns you when they differ. Streaming services also often block datacenter IPs, so a VPN location usually works better than a cheap VPS for streaming.
